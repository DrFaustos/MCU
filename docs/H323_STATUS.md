# Статус H.323

* Обновлено: 2026-09-22
* Решение: `docs/ADR-0002-h323plus-unified-media.md`

## Кратко

**H.323-стек ещё не собран, поэтому H.323-звонок пока не будет принят в
production.** Но каркас приёма уже в коде: `mcuclient/h323_endpoint.py`
слушает порт **1720** через H323Plus и заводит участников в общую комнату.

Важно: приложение **не падает**, если H323Plus не собран — `start()`
возвращает `False`, и клиент продолжает работать SIP-only. Для реального
приёма H.323 нужно собрать нативный стек: `scripts/install_h323plus.sh`
или `docker/mcu-dev-h323.Dockerfile` (Этап 0).

`mcuclient/h323_gateway.py` (GStreamer + Asterisk `chan_ooh323`) — старый
обходной путь, помечается устаревшим после проверки Этапа 1.

## Почему протокол не «выбирается» автоматически

Протокол всегда выбирает **вызывающая сторона** настройкой на своём терминале.
SIP и H.323 — два разных порта и два разных стека сигнализации. Нельзя «по одному
адресу принять и то, и другое» без явной реализации обоих стеков на одном хосте.

* Терминал настроен на **SIP** → шлёт INVITE на `room@host:5060` → наш PJSIP примет.
* Терминал настроен на **H.323** → шлёт Q.931 на `host:1720` → примет наш
  `H323Endpoint` (когда H323Plus собран).

## Что делаем (ADR-0002)

Переходим на **единый медиа-слой H323Plus** (форк willamowius) для H.323 и SIP,
по образцу OpenMCU.ru (там SIP-вызовы тоже создают `H323Connection`).
Это даёт один микшер и один PCM-конвейер без дублирования буферов.

## Что уже есть по Этапу 1

* `mcuclient/h323_endpoint.py`:
  * `H323Endpoint` — слушает 1720, авто-ответ, регистрация участников в `Room`;
  * `H323CallInfo`, `alias_to_uri()`, `state_from_h323()` — чистые функции;
  * `H323_AVAILABLE` — graceful degradation (как `PJSIP_AVAILABLE`).
* `run.py`: при `--h323` поднимает нативный эндпоинт рядом с SIP; если
  H323Plus не собран — пишет предупреждение и продолжает.
* `tests/test_h323_endpoint.py`: 22 теста (URI, состояния, регистрация,
  авто-ответ, отключение, деградация) — проходят без нативной библиотеки.

## Безопасность: закрытый контур, без сертификатов

Осознанное решение для изолированной сети (см. ADR-0002 §3.3):

* H.235 — выключено.
* SIP TLS — не используется (только UDP/TCP).
* SRTP — выключено.
* Web-интерфейс (если появится) — HTTP или локальный самоподписанный сертификат,
  без внешнего CA.
