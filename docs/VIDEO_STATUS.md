# Статус видео (Этап 4): блокер в SWIG-биндинге pjsua2

## Что проверено

1. **Сборка pjproject с видео выполнена** (`--with-ffmpeg=/usr`, v4l2, libyuv).
   Лог компиляции подтверждает флаги:
    
   `_pjsua2.so` (33 МБ) содержит `VideoMedia`, `VideoWindow`,
   `VideoPreview` и строки `H264`, `VP80`, `PJMEDIA_FORMAT_H264`,
   `PJMEDIA_FORMAT_VP8`.

2. **Видео-устройства видны:** `vidDevManager().getDevCount() == 4`.

## Блокер

Python-биндинг (SWIG-обёртка) **не экспортирует управление видео-кодеками**:

| Проверка | Результат |
|---|---|
| `codecEnum2()` видео | пусто (только аудио) |
| `ep.vidCodecEnum2()` | **отсутствует** |
| `medConfig.enableVideo` | **отсутствует** (`vidPreviewEnableNative` есть) |
| `codecSetPriority('H264/90000')` | падает с ошибкой |

Это ограничение генерации SWIG-обёртки pjsua2 2.16, а не сборки:
библиотеки собраны с видео, но Python-API для включения видео-кодека нет.

## Следствия

* **Видео-звонок через Python-биндинг технически невозможен** сейчас:
  нечем включить видео-кодек и сформировать видео в SDP.
* Запись видео (MP4 через FFmpeg) — работает независимо (см.
  `scripts/testbed/verify_video_recording.py`, PASS).
* Настройки видео в конфиге и UI сохранены (для будущих сборок).

## Варианты

1. **Собрать pjsua2 с pybind11-биндингом** (в pjproject есть экспериментальный
   `pjsua2/pybind11`) — там видео-API может быть полнее. Долго, рискованно.
2. **Заморозить видео-звонок** (как H.323) до отдельной инфраструктурной задачи.
3. **Писать видео-часть на C++/отдельном процессе**, общаясь с Python по IPC —
   крупная переработка.

Рекомендация: **вариант 2** — заморозить; всё проверяемое (аудио, чат,
запись аудио/видео, контракт stop(), CI) уже закрыто.
