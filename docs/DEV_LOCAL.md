## 2. Wayland: видео в тайлах

pjsua2 рендерит видео через native window handle (XID на X11, HWND на Windows).
На Wayland такого handle нет → тайлы пустые. Решение: запускать Qt через
XWayland (`QT_QPA_PLATFORM=xcb`). Это делается автоматически в `run.py`
до создания `QApplication` (модуль `mcuclient/qt_platform.py`).

Управление через переменную окружения `MCU_QT_PLATFORM`:

| Значение   | Поведение                                              |
|------------|--------------------------------------------------------|
| `auto`     | (по умолчанию) Wayland → xcb, X11/Windows не трогаем   |
| `xcb`      | принудительно XWayland/X11                             |
| `wayland`  | принудительно Wayland (видео не будет)                 |
| `native`   | не вмешиваться                                         |

 

Если XWayland недоступен, в лог пишется явное предупреждение.

### 6a. Если act недоступен: venv «как в CI»

`lint-and-test` ставит только `pytest`, `pytest-cov` и `ruff` — без `pjsua2`,
`numpy` и `mss`. На машине разработки они стоят, поэтому тест, тайно зависящий
от нативного биндинга, остаётся зелёным локально и падает в CI. Мини-раннер в
тех же условиях отставал от pytest на активные `skipif`-кейсы: коллекция
обязана считать их так же, как pytest, а пропускать — только на исполнении.

Тот же repro без act: поднять venv, поставить в него только pytest и прогнать
им же и `pytest tests/ -q`, и `python3 tests/_runner.py --collect-only` — числа
кейсов обязаны совпасть. Ставить `mypy`/`ruff` в системный python нельзя
(PEP 668), для них нужен такой же изолированный venv.

Случай из практики (2026-10-09): локально «1070 passed, 0 failed», CI при этом
красный на «мини-раннер 1067, pytest 1069» плюс два NAT-теста.

## 8. Полезные флаги run.py

| Флаг                  | Назначение                                   |
|-----------------------|----------------------------------------------|
| `--doctor`            | диагностика окружения и выход                |
| `--headless`          | без GUI                                      |
| `--call URI`          | headless: позвонить и выйти                  |
| `--call-wait N`       | сколько секунд ждать вызова                  |
| `--null-audio`        | null-аудиоустройство PJSIP (нет звука)       |
| `--auto-answer` / `--no-auto-answer` | авто-ответ на входящие        |
| `--list-video-devices`| список камер                                 |
| `--test-camera ID`    | превью камеры N секунд                       |
| `--no-camera/--no-mic`| старт с выключенными устройствами            |
