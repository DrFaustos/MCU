## 2. Wayland: видео в тайлах

pjsua2 рендерит видео через native window handle (XID на X11, HWND на Windows).
На Wayland такого handle нет → тайлы пустые. Решение: запускать Qt через
XWayland (`QT_QPA_PLATFORM=xcb`). Это делается автоматически в `run.py`
до создания `QApplication` (модуль `mcuclient/qt_platform.py`).

Управление через переменную окружения `MCU_QT_PLATFORM`:

| Значение   | Поведение                                              |
|------------|--------------------------------------------------------|
| `auto`     | (по умолчанию) Wayland → xcb, X11/Windows не трогаем   |
| `xcb`      | принудительно XWayland/X11                             |
| `wayland`  | принудительно Wayland (видео не будет)                 |
| `native`   | не вмешиваться                                         |

 

Если XWayland недоступен, в лог пишется явное предупреждение.

### 6a. Если act недоступен: venv «как в CI»

`lint-and-test` ставит только `pytest`, `pytest-cov` и `ruff` — без `pjsua2`,
`numpy` и `mss`. На машине разработки они стоят, поэтому тест, тайно зависящий
от нативного биндинга, остаётся зелёным локально и падает в CI. Мини-раннер в
тех же условиях отставал от pytest на активные `skipif`-кейсы: коллекция
обязана считать их так же, как pytest, а пропускать — только на исполнении.

Тот же repro без act: поднять venv, поставить в него только pytest и прогнать
им же и `pytest tests/ -q`, и `python3 tests/_runner.py --collect-only` — числа
кейсов обязаны совпасть. Ставить `mypy`/`ruff` в системный python нельзя
(PEP 668), для них нужен такой же изолированный venv.

Случай из практики (2026-10-09): локально «1070 passed, 0 failed», CI при этом
красный на «мини-раннер 1067, pytest 1069» плюс два NAT-теста.

## 9. Все флаги run.py

Полный реестр длинных флагов: парсер обязан принимать каждый
перечисленный здесь флаг, а док обязан перечислять каждый,
который парсер принимает (`build_parser()` в `run.py`). Раздел 8
остаётся списком ходовых флагов. Назначения приведены дословно
из `help` парсера, допустимые значения — из `choices`.

- `--config` — путь к config.json
- `--listen` — адрес приёма вызовов, напр. 0.0.0.0:5060
- `--display-name` — имя комнаты/дисплея
- `--transport` — SIP-транспорт; значения: udp / tcp / tls
- `--domain` — домен/адрес МСУ, который набирают терминалы (по умолчанию — вызов по IP)
- `--sip-user` — SIP-user МСУ (номер зала); по умолчанию — имя комнаты
- `--srtp` — шифрование медиа; по умолчанию off (закрытый контур); значения: off /
             optional / mandatory
- `--codec-profile` — набор кодеков (max_compat = максимум совместимости); значения:
                      max_compat / wideband / g711_only
- `--protocol` / `--proto` — протокол исходящего вызова (--call/--auto-call):
                             auto/sip/h323/h323_native; значения: auto / sip / h323 /
                             h323_native
- `--register` — регистратор, напр. sip:voip.corp:5060 (без него MCU отвечает только на
                 прямые вызовы по IP)
- `--reg-user` — имя абонента/номер зала для регистрации
- `--reg-password` — пароль абонента (надёжнее env MCU_REG_PASSWORD — в cmdline его
                     видно через ps)
- `--reg-domain` — домен для SIP-URI (по умолчанию хост регистратора)
- `--h323` — включить H.323-шлюз
- `--h323-port` — порт H.323 (по умолчанию 1720)
- `--h323-socket` — unix-сокет C++-хоста mcu_h323d (Вариант B, ADR-0002)
- `--headless` — без GUI
- `--doctor` — диагностика окружения (pjsua2, порт, устройства, графика) и выход
- `--call` — headless: позвонить на SIP URI/IP и выйти (тест исходящего вызова)
- `--auto-call` — GUI: сразу позвонить на SIP URI/IP после старта
- `--call-wait` — headless: сколько секунд ждать вызова (по умолчанию 30)
- `--web` — включить встроенную web-панель управления
- `--no-web` — выключить web-панель (перекрывает config)
- `--web-host` — адрес web-панели (по умолчанию 0.0.0.0)
- `--web-port` — порт web-панели (по умолчанию 8080)
- `--web-token` — токен авторизации web-панели (иначе env MCU_WEB_TOKEN)
- `--web-tls` — включить HTTPS для web-панели (по умолчанию HTTP)
- `--no-web-tls` — выключить HTTPS (перекрывает config)
- `--web-cert` — путь к TLS-сертификату (PEM)
- `--web-key` — путь к TLS-ключу (PEM)
- `--list-video-devices` — показать видеоустройства и выйти
- `--test-camera` — показать локальное превью камеры с указанным ID и выйти
- `--camera-device` — выбрать камеру по ID для звонка
- `--no-camera` — старт с выключенной камерой
- `--no-mic` — старт с выключенным микрофоном
- `--null-audio` — использовать null-аудиоустройство PJSIP (headless/CI)
- `--auto-answer` — автоматически принимать входящие вызовы
- `--no-auto-answer` — не принимать входящие автоматически
- `--preview-seconds` — длительность теста камеры, сек (по умолчанию 5)
- `--verbose` — подробные логи
