# Локальный контейнерный стенд MCU (2 клиента)

Быстрый способ проверить реальный SIP-звонок между двумя клиентами MCU
**локально**, не дожидаясь сборки AppImage/`.exe` в GitHub Actions.

Стенд поднимает два контейнера в одной bridge-сети:

| Контейнер | IP         | Роль                        |
|-----------|------------|-----------------------------|
| `mcu-a`   | 10.0.3.10  | клиент A (звонит)           |
| `mcu-b`   | 10.0.3.20  | клиент B (принимает)        |

Внутри сети нет NAT — SIP/RTP идут напрямую, ICE/STUN не нужны.

## 2. Запуск стенда

 

Скрипт сам определяет:

* **GUI**: если задан `DISPLAY` и есть `/tmp/.X11-unix`, окна обоих клиентов
  выводятся на экран разработчика (через XWayland, `QT_QPA_PLATFORM=xcb`).
  Иначе контейнеры стартуют в `--headless`.
* **Звук**: если есть PulseAudio-сокет `/run/user/<uid>/pulse/native`, он
  пробрасывается; иначе клиенты стартуют с `--null-audio` (тестируется
  сигналинг и видео без реального звука).

Переменные для управления:

| Переменная   | Значение | Смысл                                  |
|--------------|----------|----------------------------------------|
| `MCU_X11`    | `auto`/`x11`/`headless` | Режим вывода GUI          |
| `MCU_SUBNET` | CIDR     | Подсеть (по умолчанию `10.0.3.0/24`)   |
| `MCU_A_IP` / `MCU_B_IP` | IP | Адреса контейнеров                |
| `MCU_SIP_PORT` | порт   | SIP-порт (по умолчанию `5060`)         |
| `MCU_IMAGE`  | имя      | Рабочий образ (по умолчанию `mcu-dev`) |

## 6. Ограничения и fallback

* **Вложенные контейнеры недоступны** в некоторых средах (нет capabilities,
  `unshare --net` запрещён). Тогда используйте процессный стенд:
   
* **Screen share** в контейнере без X-сессии не тестируется — нужен
  `v4l2loopback` плюс реальная X-сессия.
* Если окна не появляются: проверьте `echo $DISPLAY` на хосте и наличие
  `/tmp/.X11-unix`. На чистом Wayland без XWayland GUI не вывести — используйте
  headless-режим и `scripts/dev/test_call.sh`.
* Перед первым запуском проверьте окружение: `python3 run.py --doctor`.
