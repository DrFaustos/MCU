# Выбор протокола исходящего вызова (SIP / H.323)

**Статус: реализовано (v0.2.29).** Модуль `mcuclient/call_proto.py`,
GUI, CLI `--proto`, ключ `features.default_call_protocol`.

## Зачем это нужно

До v0.2.29 протокол исходящего вызова выбирался неявно — по префиксу URI
(`h323:` → H.323, всё остальное → SIP). Из-за этого нельзя было:

* позвонить по **голому IP** именно по H.323 (например, на аппаратный
  терминал Sony/Polycom, которому нужен H.225/H.245, а не SIP INVITE);
* принудительно выбрать **нативный H.323-стек** (H323Plus через хост
  `mcu_h323d`) вместо legacy GStreamer-шлюза — и наоборот;
* воспроизводимо прогонять тесты совместимости: «этот же адрес, но
  протокол X».

Теперь протокол выбирается явно: в GUI, в CLI и в конфиге.

## Ключи протоколов

| Ключ | Название | Реализация |
|------|----------|------------|
| `auto` | Авто (по адресу) | выбор по префиксу, см. ниже |
| `sip` | SIP (PJSIP) | `SipEngine.call()` → `pjsua2` |
| `h323` | H.323 — шлюз (GStreamer) | `H323Gateway.call()` → `gst-launch-1.0` |
| `h323_native` | H.323 — нативный (mcu_h323d) | `H323Endpoint.make_call()` → H323Plus через IPC |

## Режим «Авто»

* адрес начинается с `h323:` / `h323s:` → H.323;
* адрес начинается с `sip:` / `sips:` → SIP;
* всё остальное (голый IP, `100@host`, E.164) → **SIP** (историческое
  поведение движка).

Если определён H.323 и доступен нативный хост (`mcu_h323d` подключён),
«Авто» предпочтёт `h323_native`; иначе откатится на GStreamer-шлюз `h323`.

> Чтобы позвонить по **голому IP** именно по H.323, выберите протокол
> вручную (`h323` или `h323_native`) — в GUI или через `--proto`.

## GUI

В строке вызова рядом с полем адреса есть выпадающий список **Протокол**
со всеми четырьмя вариантами. Выбранный протокол применяется к нажатию
**Call** и к `--auto-call`.

## CLI

    python run.py --proto {auto,sip,h323,h323_native} --call <адрес>
    python run.py --proto h323_native --auto-call <адрес>   # GUI

`--proto` задаёт протокол по умолчанию и для GUI, и для `--call`/`--auto-call`.
Если флаг не задан, берётся `features.default_call_protocol` из конфига
(по умолчанию `auto`).

Примеры:

    # нативный H.323 на аппаратный терминал
    python run.py --proto h323_native --call 192.168.1.60

    # SIP-вызов
    python run.py --proto sip --call sip:100@192.168.1.50

    # H.323 через GStreamer-шлюз
    python run.py --proto h323 --call h323:192.168.1.60

## Конфигурация

    {
      "features": {
        "default_call_protocol": "auto"
      }
    }

Значение проверяется при загрузке конфига: допускаются только
`auto`, `sip`, `h323`, `h323_native`; иначе `ConfigError`.

## Программный API

    from mcuclient import call_proto

    target = call_proto.resolve_call(
        "auto", "h323:192.168.1.60", native_available=True
    )
    if not target.ok:
        print("Нельзя позвонить:", target.error)
    else:
        print(target.protocol, target.address)
        # -> h323_native 192.168.1.60

`resolve_call(proto, uri, *, native_available=False)` возвращает
`CallTarget(protocol, address, error)`. При ошибке (пустой адрес, только
префикс, запрошен нативный H.323 без хоста) `target.ok == False`, а
`target.error` содержит понятное объяснение.

## Ошибки и деградация

| Ситуация | Поведение |
|----------|-----------|
| Выбран `h323_native`, хост не запущен | вызов отклоняется с сообщением «нативный H.323 недоступен» |
| Выбран `h323`, GStreamer/плагинов нет | `H323Gateway.call()` вернёт `False`, в статусе — «шлюз недоступен» |
| Выбран `sip`, `pjsua2` нет | `SipEngine.call()` вернёт `None`, событие `call.error` |
| Пустой адрес / только `h323:` | вызов не начинается, сообщение об ошибке |

## Тесты

`tests/test_call_proto.py` — 23 юнит-теста чистой логики: алиасы ключей,
определение по префиксу, снятие префикса, приоритет нативного H.323 в
«Авто», откат на шлюз, обработка пустых/битых адресов, метки протоколов.
Тесты не требуют ни `pjsua2`, ни GUI.
