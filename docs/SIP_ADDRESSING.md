# Адрес МСУ в SIP: как нас набирают

Документ про одну строку в конфиге — `sip.identity.domain` — и про то,
почему вокруг неё отдельный модуль (`mcuclient/sip_address.py`).

Первичный сценарий проекта — **закрытый контур без DNS и без шифрования**,
где в MCU звонят **по IP**. Отсюда главное правило:

> пустой «домен» — это НЕ ошибка и НЕ «адрес не настроен». Это штатный
> режим «звонок по IP», и MCU обязан в этом режиме набираться.

## Где настройка живёт и кто её меняет

```
config.json → sip.identity.{domain,user,display_name}
```

Меняют её из четырёх мест, и все четыре обязаны понимать её одинаково:

| Вход | Код |
|------|-----|
| нативный GUI (панель «Адрес МСУ») | `mcuclient/ui.py` → `engine.apply_sip_settings()` |
| web-панель (`POST /api/address`) | `mcuclient/web_server.py` → тот же метод движка |
| конфиг-файл | `mcuclient/config.py` |
| командная строка | `run.py --domain ... --sip-user ...` |

Реализация одна — `SipEngine.apply_sip_settings()`: `account.modify()` с
новым `idUri`, без перезапуска pjsua2 (второй `start/stop` в одном процессе
валит процесс). Поэтому «что показывает Qt» и «что делает браузер» не
могут разойтись.

## Единственная точка нормализации

`mcuclient/sip_address.py` — чистые функции без pjsua2 и без Qt, покрытые
`tests/test_sip_address.py`. Правила:

* **`normalize_domain()`** — из того, что набрал оператор
  (`" sip:MCU@Hall:5060 "`, `"sips:[2001:db8::1]:5061"`, `"2001:db8::1"`)
  делает хост для URI:
  * схема (`sip:` / `sips:`) снимается, `sips:` = TLS;
  * голый IPv6 **получает обязательные скобки** — хост с `:` вне скобок
    невалиден в SIP-URI, и без этого Contact получался мёртвым молча;
  * пробел/кириллица/`<>`/`;` → пустая строка, т.е. «не применяем»
    (движок честно сядет на IP и предупредит), а не «починим как-нибудь».
* **`sanitize_sip_user()`** — имя комнаты «Зал 1» → `1`, `MCU Room` →
  `MCU-Room`. pjsip URI с пробелом не разбирает и при этом молчит.
* **`parse_host_port()`** — `host:port`, `[v6::1]:5060`; порт вне
  диапазона → `(хост, 0)`, а не «подставим дефолт».

## Выбор хоста для idUri / Contact

`resolve_identity()` возвращает `AddressReport`. Порядок:

1. `sip.identity.domain` — его наберают терминалы;
2. `sip.nat.public_address` — белый IP за статичным NAT 1:1 (иначе BYE и
   обратные INVITE уйдут в частную сеть);
3. конкретный `sip.listen` (не `0.0.0.0`);
4. IP машины (UDP-connect трюк) → `host_source == "auto"` + предупреждение.

`0.0.0.0`/`::`/`*` в Contact не попадают никогда — на них нельзя
позвониться.

### Порт: «набирать сюда» ≠ «слушать здесь»

Частая ошибка операторов и частый баг: написать в домене `mcu.corp:5065` и
перенести этот порт в `sip.port`. Тогда MCU перестаёт слушать 5060, куда
звонят все остальные, а в Contact порт наоборот пропадает.

Правило, зафиксированное тестами:

* порт из адреса доезжает **только в URI** (`rep.port`, `rep.uri`);
* `sip.port` (порт транспорта) setter'ы не трогают;
* стандартный схемы (`5060`, `5061` для `sips`) в URI не пишется —
  терминал подставит сам;
* `sips:` без явного порта = 5061, иначе URI обещает не то, что слушаем.

### Что показывает панель

`to_dict()` отдаёт и `uri` (значение Contact/idUri), и `summary` — строку
вида `Звонить: sip:6001@mcu.corp:5060 (также sip:6001@10.0.0.5:5060)`.

`dial_targets` **всегда** содержит IP-вариант, даже когда в URI поехал
домен: в закрытом контуре без DNS IP — часто единственный способ
дозвониться, и оператору незачего гадать.

## Регистрация на АТС/CUCM

Если включена регистрация (`sip.registration`), пользователем линии
становится имя абонента, а хостом — **домен**: на CUCM/Voisica линия
ищется как `user@domain`, и `user@10.0.0.5` регистратор отбивает
(403/404). см. `mcuclient/sip_registration.py::build_id_uri`.

IPv6-хост там же обязан уезжать в скобках: обычная чистка
`[^A-Za-z0-9._-]+ → '-'` превращает `2001:db8::1` в `2001-db8--1`, и
«конфиг правильный, не работает» без единой ошибки в логе.

## Шифрование по умолчанию выключено

`srtp: "off"`, web-панель на HTTP, `sips`/TLS не участвуют в
установлении соединения. Переключатели есть (`POST /api/encryption`), но в
закрытом контуре это «на всякий случай». HTTPS панели никогда не должен её
ронять: если сертификат не поднялся, сервер перезапускается на HTTP
(`web_server.set_web_tls`).
