# Архитектура MCU Client

## 1. Назначение

Клиент-приложение уровня MCU для видеоконференцсвязи:

* приём **входящих** вызовов и **исходящие** вызовы к аппаратным и программным ВКС;
* протоколы **SIP** и **H.323**;
* аудио + видео, согласование кодеков;
* использование **камеры** и **микрофона** с вкл/выкл на лету;
* регулирование качества, битрейта и полосы;
* **одна комната**, автосоздаваемая при старте;
* приём вызовов **только по сети по IP**;
* Windows 10/11 и Linux.

## 3. SIP-движок (pjsua2)

* `Endpoint` — инициализация PJSIP, транспорт UDP/TCP/TLS.
* `Account` — аккаунт без регистрации: URI `sip:<room>@<listen>`.
* `onIncomingCall` — приём входящего. Проверяется IP удалённой стороны
  через `PeerFilter`; неразрешённые отклоняются (486 Busy Here).
* `makeCall` — исходящий вызов (`sip:` добавляется автоматически, если нет схемы).
* Приоритеты кодеков выставляются `codecSetPriority` на основе
  `config.sip.codecs` (сначала аудио, затем видео).
* Согласование кодеков — стандартный SDP offer/answer (audio + video).
* Инициализация Endpoint выполняется с `uaConfig.threadCnt = 0`: внутренние
  worker-потоки PJSUA2 несовместимы с Python-биндингом pjsua2 (нативные
  assertion/segfault без Python-трейсбэка). Вся работа PJSIP идёт в
  вызывающем (главном) потоке — см. `SipEngine._start_pjsip`.

## 4. Комната

Одна комната (`Room`) создаётся автоматически при `SipEngine.start()`.
Все вызовы (входящие и исходящие) регистрируются как `Participant` в комнате.
Участник хранит URI, состояние (`CallState`), выбранные кодеки и битрейты.

## 5. Медиа

* `MediaState` — состояние камеры/микрофона, список устройств.
* `_apply_media_state` применяет вкл/выкл камеры к активным вызовам
  (`vidSetStream`), микрофон — через `pjmedia`.
* Качество: `set_video_quality(w, h, fps)`; битрейт видео/аудио и общая полоса
  задаются слайдерами в UI и сохраняются в конфиге.

## 6. H.323

Зрелого H.323-стека на Python нет. `H323Gateway`:

1. проверяет наличие `gst-launch-1.0` и элементов `h323`/`openh323`;
2. при наличии запускает пайплайн приёма на `h323.port` (по умолчанию 1720);
3. умеет инициировать исходящий вызов на IP/E.164;
4. при отсутствии GStreamer/H.323 сообщает статус и не мешает SIP.

**Почему не in-process.** Готовых Python-биндингов для H.323 нет:
доступны только C++-стеки H323Plus и OPAL (у OPAL ограниченный C API).
Поэтому единственный рабочий путь — внешний шлюз, а не собственная
реализация H.225/H.245 на Python.

**Рабочая реализация** (см. `docs/H323_STATUS.md`): Asterisk +
`chan_ooh323` (ooh323c, Objective Systems) как H.323↔SIP-шлюз.
Python-движок H.323 не парсит — общается по SIP.

## 6a. Микширование (важное ограничение)

PJSIP — это **не MCU-микшер**, а SIP-стек с conference bridge.

* **Аудио**: conference bridge PJSIP микширует потоки (несколько участников
  слышат друг друга) — используется штатно.
* **Видео**: микширование в PJSIP **не реализовано** (в документации прямо:
  "this is not implemented yet"). Видео только **роутится/сплиттится**
  (адресация потоков между участниками), но не комбинируется в общую картинку.

**Следствие для позиционирования.** Проект фактически является
**SFU/роутером + аудио-микшером**, а не полным MCU с видео-миксом.
Если требуется видео-микс (общая раскладка/композиция) — его нужно
выносить в отдельный компонент (FFmpeg/GStreamer), а PJSIP оставлять
транспортом. В коде это соответствует `ConferenceRecorder` +
`ScreenSharer`/`VideoSourceSwitcher`, а не встроенному видео-микшеру.

## 7. Фильтр входящих по IP

`PeerFilter` принимает список `allowed_peers` (`192.168.1.0/24`, `10.0.0.5`).
Пустой список — разрешены все. Проверка выполняется до ответа на INVITE.

## 8. Зависимости

| Компонент   | Библиотека            |
|-------------|-----------------------|
| SIP/RTP     | PJSIP (pjsua2)        |
| GUI         | PySide6 (Qt 6)        |
| H.323       | Asterisk + chan_ooh323 (внешний шлюз); GStreamer/openh323 — вспомогательно |
| Камеры/мики | V4L2 / Media Foundation |

## 9. Режимы отказа

* Нет `pjsua2` → движок в режиме-заглушке, GUI работает, вызовы недоступны.
* Нет `PySide6` → `--headless` (серверный режим).
* Нет GStreamer/H.323 → H.323 отключён, SIP работает штатно.
