# mcu_h323d — H.323-хост единого медиа-слоя

Отдельный C++-процесс на **H323Plus**, который слушает порт **1720** и
управляет H.323-вызовами. Python-клиент (`mcuclient/h323_host.py`)
общается с ним по **unix-сокету** через newline-delimited JSON.

## Зачем отдельный процесс

Python-биндингов H323Plus **не существует**. H323Plus — callback-тяжёлый
C++-стек, владеющий RTP/PCM/кодеками; держать его в Python-процессе нельзя
(GIL, утечки, падения нативного кода). Поэтому H323Plus живёт в своём
процессе, а Python остаётся оркестратором и микшером — см.
`docs/ADR-0002-h323plus-unified-media.md` (Вариант B).

## Сборка

Требует собранных PTLib + H323Plus (`scripts/install_h323plus.sh`).

Точка входа — `main.cpp`; IPC и JSON — header-only (`ipc.hpp`, `json.hpp`).

## Запуск вручную (для отладки)

 

При старте хост печатает `[mcu_h323d] H.323 слушает 0.0.0.0:1720`, а событие
`ready` шлёт в момент подключения Python-клиента (а не при старте), чтобы
готовность не терялась, пока клиента ещё нет.

## Протокол IPC

Одна JSON-строка на сообщение, разделитель — `\n`.

### Хост → Python (события)

| Событие | Поля | Смысл |
|---------|------|-------|
| `ready` | `port`, `name` | Эндпоинт поднят; шлётся при подключении клиента |
| `pong` | — | Ответ на `ping` |
| `call.incoming` | `token`, `alias`, `ip` | Входящий H.323-вызов |
| `call.connected` | `token`, `alias`, `ip` | Вызов установлен |
| `call.disconnected` | `token`, `alias`, `ip`, `reason` | Вызов завершён |
| `error` | `message` | Ошибка обработки команды |
| `shutdown` | — | Хост завершается |

### Python → хост (команды)

| Команда | Поля | Смысл |
|---------|------|-------|
| `ping` | — | Проверка связи (ответ `pong`) |
| `call.answer` | `token` | Ответить на вызов |
| `call.hangup` | `token` | Завершить вызов |
| `shutdown` | — | Остановить хост |

## Медиа (следующий шаг)

Сейчас по IPC идёт только **сигнализация/управление вызовами** (Этап 1):
H.323-звонок принимается, участник попадает в общую комнату. Передача PCM
между хостом и Python-микшером (`mcuclient/audio_mixer.py`) — следующий
шаг: отдельный бинарный канал (shmem/pipe), чтобы не смешивать с JSON.
